# Runforge

Frontend страницы Runs платформы RunForge: просмотр запусков AI-агентов, поиск, фильтрация и подробности с логами. Приложение работает без настоящего бэкенда — HTTP-запросы перехватывает MSW.

Стек: React, TypeScript, Vite и CSS Modules. Состояние хранится локально в React, без дополнительных библиотек роутинга и глобального состояния.

## Возможности

- Поиск по названию и репозиторию, фильтрация по статусу.
- Сортировка по дате и длительности.
- Сохранение поиска, фильтра и сортировки в URL.
- Drawer с подробностями, логами и результатом.
- Адаптивная таблица с карточками на мобильных устройствах.
- Обработка ошибок с показом Retry.
- Обработка пустых результатов поиска с возможностью сбросить фильтры.

## Структура

Код организован по FSD: страница использует публичный API сущности Run, а сервис не зависит от моков.

```text
src/
├── app/
│   ├── mocks/          # Fixtures, обработчики и браузерная настройка MSW
│   ├── styles/         # Общие стили и CSS-переменные
│   └── tests/          # Настройка тестовой среды
├── entities/run/
│   ├── api/            # getRuns(): получение запусков через fetch
│   ├── lib/            # Форматирование дат и длительности
│   ├── model/          # Типы Run и RunStatus
│   ├── ui/             # Бейдж статуса
│   └── index.ts        # Публичный API сущности
├── pages/runs/
│   ├── model/          # Загрузка, поиск, сортировка и синхронизация с URL
│   ├── ui/             # Страница, список, панель фильтров, drawer и состояния
│   ├── tests/          # UI-тесты страницы
│   └── index.ts        # Публичный API страницы
├── App.tsx             # Композиция приложения
└── main.tsx            # Запуск MSW перед отрисовкой React
```

Стили компонентов находятся рядом с ними в файлах `*.module.css`.

## Запуск

```sh
npm install
npm run dev
```

Приложение доступно по адресу http://localhost:5173. Если порт занят, Vite завершится с ошибкой: освободите порт и повторите запуск.

## Сборка

```sh
npm run build
```

Команда проверяет типы TypeScript и собирает приложение в `dist/`. Для локального просмотра сборки выполните `npm run preview`.

## Mock API

MSW мокирует запросы к бэкенду в браузере: `getRuns()` делает обычный `fetch` к `GET /api/runs`, а MSW возвращает JSON с задержкой 700 мс. MSW запускается до отрисовки React, чтобы перехватить первый запрос.

- **Мок-данные:** `src/app/mocks/fixtures/runs.ts` — восемь фиксированных запусков, по два каждого статуса, с логами и примерами отсутствующих результата и длительности.
- Обработчики запросов: `src/app/mocks/handlers.ts`.

Моки включены и при разработке, и в production-сборке демо. Для отключения задайте `VITE_ENABLE_MOCKS=false` при запуске dev-сервера или сборке; тогда потребуется настоящий API.

Для проверки ошибки откройте страницу с `?mockError=1`: `getRuns()` передаст флаг в API-запрос. Первый запрос вернёт HTTP 500, после Retry — HTTP 200. Перезагрузка страницы сбрасывает сценарий.
